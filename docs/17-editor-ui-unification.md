# 17. 编辑器 UI 统一与易用性:设计方案

> 需求(2026-10-16 用户提出):
> ① 统一编辑 UI —— 标注工具逻辑本就一样,收敛到一套代码,UI 自然统一;
> ② 编辑页文字太多,适当用图标;
> ③ 标注浮条加**透明度调节**,尽量不挡原图;
> ④ 继续完善编辑功能,让编辑器更好用。
> **未完全实现好之前不提交代码。**

## 17.1 现状(已核实的证据)

### 三套编辑宿主,能力同源、UI 各写一份

| 入口         | 宿主                    | 工具数 | UI 实现                                  | 文字输入                     |
| ------------ | ----------------------- | ------ | ---------------------------------------- | ---------------------------- |
| 截图框选浮条 | \`OverlayWidget\`       | 10     | **自绘**(\`drawToolbar\`/\`drawSubbar\`) | 宿主 \`QLineEdit\` 单行      |
| 右键「编辑」 | \`EditorWindow\`        | 10     | 两行 \`QToolBar\`                        | \`QGraphicsTextItem\` 可换行 |
| 贴图「✎」    | → 也开 \`EditorWindow\` | 10     | 同上                                     | 同上                         |

能力层**早已统一**(S2 抽出的 \`AnnotationEngine\`),差异全在宿主 UI:

- 工具集同源但各写一份:\`editor_window.cpp:244\` 的 \`kTools[]\` 与
  \`capture_session.cpp\` 的 \`toolOrder()\` 是两份平行数组;
- 调色板七色同样两份(\`kPalette[]\` / \`paletteColors()\`);
- 粗细/字号档位 \`{2,4,8}\` / \`{24,36,48}\` 又是两份。

### "标注不好用"的直接原因(代码可证)

| #   | 现象                                                                | 证据                                                                      |
| --- | ------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 1   | 画布**只能画、不能看**:无抓手平移,左键一按就是画笔                  | \`editor_window.cpp:173\` \`setDragMode(NoDrag)\`                         |

| 3   | 外观与产品割裂:编辑器用 Qt 默认浅色窗体,浮条/贴图工具条是深色       | \`main.cpp\` 无全局样式;浮条底板 \`capture_session.cpp:903\`              |
| 4   | 工具按钮纯文字,无图标,两行文字又占地方                              | \`editor_window.cpp:284/295\` "粗细 2"/"字号 36"                          |

### 浮条挡视线的原因(需求 ③)

底板颜色**硬编码近乎不透明**,且**无法调节**:

- 主浮条 \`capture_session.cpp:903\`:\`QColor(0x26,0x27,0x2E,242)\`
- 二级条 \`capture_session.cpp:1183\`:同一个值

242/255 ≈ 95% 不透明 —— 压在选区底部时正好盖住待截内容。

### 已有的可复用资产

- **主题系统**:\`Theme.qml\`(dark/light 两套色板)+\`CoreFacade::applyTheme\`
  (\`core_facade.cpp:153\`)注入 **QPalette**,Basic 风格控件自动跟随。
  → **编辑器是 QWidget,天然吃 QPalette**,统一外观的落点就在这里。
- **矢量图标词汇**:\`HeaderIcon.qml\` 纯 QML 几何绘制(16px 视口、1.5px 描边、
  零图片资源),\`docs/theme.md §38\` 约定"只用几何图形,不用字体字形/emoji"。
- **不透明度先例**:贴图窗口 \`pin_window.cpp:215\` 的 \`QSlider\`(30–100),
  设置键 \`pin_default_opacity\`(\`settings.rs:61\`,校验 30..=100)。

## 17.2 设计原则

1. **能力单源,外观单源** —— 工具/颜色/档位元数据只定义一次;渲染只有一套。
2. **不改变两条链路的既有语义** —— 浮条仍是"先点标注再画"的就地流程,
   编辑器仍是"打开即可画";统一的是**控件**,不是**流程**。
3. **增量落地,每步可独立验证** —— 不做大爆炸重构,先易后难。

## 17.3 方案

### A. 抽出「标注工具条」共享控件(需求 ①)

新增 \`app/src/editor/annotation_toolbar.{hpp,cpp}\`:一个**真 QWidget**,
持有 \`AnnotationEngine*\`,负责:

- 工具行(10 个,F5 图标化)
- 颜色行(七色)
- 粗细 / 字号(档位随当前工具显隐)
- 撤销 / 重做

对外只暴露:\`setEngine(AnnotationEngine*)\` + \`refresh()\`。内部状态全部来自引擎
(工具/颜色/粗细/字号都在引擎里),**不复制一份**,天然不会漂移。

同时把散落的元数据收成**单一来源**(放 \`annotation_engine.hpp\` 或新
\`annotation_meta.hpp\`):

\`\`\`cpp
const QList<EditorTool>& toolbarTools();      // 工具顺序
const QList<QColor>&     annotationPalette(); // 七色
const QList<int>&        strokeSizes();       // {2,4,8}
const QList<int>&        fontSizes();         // {24,36,48}
\`\`\`

现有三处重复数组(\`editor_window.cpp:244\`、\`capture_session.cpp\` 的
\`toolOrder()\`/\`paletteColors()\`/\`penSizes()\`/\`fontSizes()\`)全部改为引用它。

**浮条如何接**:浮条现在是 \`paintEvent\` 自绘(\`drawToolbar\`/\`drawSubbar\`)。
改为**向遮罩窗口挂子控件**(\`AnnotationToolbar\` + 主浮条),好处是绘制/命中/
高亮全部由 Qt 负责 —— 现存的"绘制与命中测试各写一份算式"这一整类缺陷随之消失
(上一轮已在 \`subbarCells()\` 里手工弥合过一次)。

> 取舍:浮条当前是"整窗自绘 + 手动命中"(\`toolbarContains\`/\`subbarContains\`)。
> 换成子控件后事件分发交给 Qt,代码净减少。**风险点**在遮罩是全屏无边框窗口、
> 子控件需显式 \`raise()\` 且不能被 \`paintEvent\` 覆盖 —— 需实测。

### B. 图标化(需求 ②)

编辑器是 C++ QWidget,拿不到 \`HeaderIcon.qml\`。两条路:

| 方案                    | 做法                                                                | 取舍                             |
| ----------------------- | ------------------------------------------------------------------- | -------------------------------- |
| **B1 代码绘制 QIcon**   | 在 C++ 里用 \`QPainter\` 画几何图标(与 HeaderIcon 同一套造型语言)   | 与 QML 端**两份造型**,长期会漂移 |
| **B2 QML 侧也复用一个** | 把图标做成 QML 组件再由 C++ 用 \`QQuickImageProvider\`/离屏渲染取图 | 跨语言桥,复杂度高                |

**建议 B1**,但**把造型集中到一个文件** \`app/src/editor/tool_icons.{hpp,cpp}\`,
函数签名 \`QIcon toolIcon(EditorTool, int size)\`。同时**顺带收敛文字**:

- 工具行:图标 + ToolTip(文字只留悬浮提示)→ 直接解决"文字太多";
- 粗细/字号:图标(圆点大小/字号示意)替代 "粗细 2"/"字号 36";
- 撤销/重做/完成/取消等动作也图标化,配 ToolTip。

> 说明:与 \`docs/theme.md §38\` 的"不用字体字形/emoji"一致 —— 全用几何绘制。

### C. 浮条透明度(需求 ③)

现状硬编码 \`alpha=242\`。设计:

- 引入**浮条不透明度**设置,范围与先例对齐(\`pin_default_opacity\`:30–100);
- 新设置键 \`captureBarOpacity\`(默认建议 **85**,即 alpha≈217,已明显减轻遮挡);
- \`drawToolbar\`/\`drawSubbar\` 的底板改用该值,并在**文字/图标**上做对比度兜底:
  不透明度低于某阈值时加深描边或改用实色文字,避免"透到看不清按钮";
- 交互:浮条上提供快捷调节(滚轮 / 小幅滑块),同时写回设置持久化。

> 待定(见 §17.5 D1):是**一键三档**(不透明/半透/极简),还是**连续滑块**。

### D. 编辑器易用性(需求 ④)

按"痛点 ÷ 成本"排序:

1. **抓手平移**(成本低,收益高):空格拖拽或中键拖拽平移;\`setDragMode\`
   在按住时切 \`ScrollHandDrag\`。解决"放大后移不动"。
2. **缩放复位入口**(成本极低):\`Ctrl+0\` 适应窗口、\`Ctrl+1\` 100%;
   并让"适应窗口"清除 \`userZoomed\` 标记。解决"滚过就回不去"。
3. **纳入主题**(成本低):编辑器已是 QWidget,\`applyTheme\` 的 QPalette 已经生效;
   需要补的是 \`QToolBar\` 自身的样式与深色底板,与浮条观感对齐。
4. **窗口尺寸记忆**(成本低):几何写入设置,下次同尺寸打开。
5. **OCR 结果面板**(成本中):结果已在剪贴板 → 明确提示"已复制,可 Ctrl+V",
   并提供"插入为标注文字"入口(把 OCR 文本直接落到画布),而不是"只展示"。

## 17.4 实施顺序(每步独立可验证)

| 步  | 内容                                                                         | 依赖             | 验证                            |
| --- | ---------------------------------------------------------------------------- | ---------------- | ------------------------------- |

### D1/D2 落地细则:一键三档(不用滑块)

浮条空间紧张,且截图时不该精细调节 —— 三档已覆盖"看清原图 ↔ 看清按钮"的全部需要,
故用**档位按钮循环切换**,不放连续滑块。

| 档         | 底板 alpha | 视觉   | 适用                 |
| ---------- | ---------- | ------ | -------------------- |
| 不透明     | 242        | 现行为 | 底色复杂、需看清按钮 |
| 半透(默认) | 217        | 略透   | 大多数情况           |
| 极简       | 179        | 明显透 | 贴近"不挡原图"       |

- 档位写入设置 `captureBarOpacity`,取值限定这三档,默认 217
  (与 `pin_default_opacity` 的 30..=100 校验同一手法);
- **对比度兜底**:极简档底板仅 70% 不透明,故 alpha 低于阈值时按钮文字改
  实色 + 细描边,避免"透到看不清";
- 切换即时生效(仅 `update()`,不重开会话),并持久化到设置。

### D5 落地细则

编辑器动作行同时保留「另存为」与「完成」,语义区分:

- 「另存为」→ 只写文件,**不入库、不写剪贴板、不关窗**(可继续编辑);
- 「完成」→ 入库 + 写剪贴板(现行为)。

2. **编辑器改动影响三条链路**(截图浮条编辑 / 右键编辑 / 贴图编辑都汇聚到
   \`EditorWindow\`):S2/S6 必须三条都回归。
3. **图标两份造型**(B1):已在 §17.3 B 说明取舍,用集中文件 + 注释互指缓解。

# 18. 第二轮反馈:设置语义重构与输入交互(设计方案)

> 用户反馈(2026-10-17),逐条查证后整合。**未实现好之前不提交。**

## 18.1 抓手平移改为默认(需求 ①)

**现状**:画布 setDragMode(NoDrag),左键一按就是画笔;平移需按住空格/中键。

**改为**:默认即抓手(ScrollHandDrag),**选中绘图工具后**才切成可绘制。

| 状态 | dragMode | 左键行为 |
| --- | --- | --- |
| 初始 / 未选工具 | ScrollHandDrag | 拖动平移画面 |
| 点击某绘图工具后 | NoDrag | 在画布上绘制 |

- 光标随之:OpenHandCursor ↔ 该工具的光标(复用已有的 toolCursor())。
- 保留空格临时平移(在绘制工具下按住空格仍可平移,不必切回)。
- 影响面:EditorCanvas::setPanning 语义从"临时开关"变为"默认态 + 工具覆盖"。

## 18.2 文字工具:一次点选,连续落多个(需求 ②,已按用户纠正)

> ⚠️ **本文档初稿把用户的第一封反馈读反了**:那句"只能编辑一次(确定后,再想加入
> 新的文字,必须再次点击工具栏的编辑文字)"是**在描述痛点**,不是目标行为。
> 目标是相反方向 —— 见下。此处保留更正痕迹,避免后人再按错误方向改。

**目标**:点一次工具栏「文字」后,可以**连续在图上落多个文本框**;
不需要"点一次工具 → 只能加一个 → 再去点一次工具"。

**现状(为什么只能加一次)**:文字编辑态靠 passthrough 把鼠标事件交给
QGraphicsView(文本控件要收键盘/光标)。而 passthrough 只在
bakeTextItem() 里收紧, bakeTextItem() 又只在**切工具/保存/完成/贴图/OCR**
时被调 —— 用户"点到别处"并不会烘焙,于是:

- m_textItem 一直非空 → editingText() 恒真 → passthrough 恒真;
- 画布再也不发 canvasPressed → 引擎再也收不到点击 → **加不了第二个文字**;
- 想继续加,只能去点工具栏换工具再换回来(= 用户描述的"必须再次点击工具栏")。

**改法**:文字编辑态下,点击**落在当前文字图元之外**时视为"确认这一段,
并就地开始下一段":

    EditorCanvas 按下(左键)
      └─ 文字编辑中?
           ├─ 点在当前文字内  → 交给 QGraphicsView(定位光标/选中),不新建
           └─ 点在文字之外    → 烘焙当前文字 → 用当前工具就地落新文字
                (工具仍是「文字」,所以可以一段接一段地加)

- 结束连续加字:点别的工具(切工具会自动烘焙),或按 Esc(见下);
- **Esc 语义修正**:编辑文字时 Esc 只**确认当前文字**,不再直接关掉整个编辑器
  (原先 Esc 无条件 cancel(),写一半的字连同编辑器一起没了);
- 引擎新增 editingTextContains(scenePos):判断点击是否落在正在编辑的文字上
  (用图元的场景包围盒 + 少量容差)。

## 18.3 「勾选项自动变回去」——已复现,根因是**陈旧快照全量覆盖**(缺陷)

**实测证据**(用真实 nbcore.dll 走 FFI 往返):

    场景 A:两个设置快照交错保存
      A 改 regionSkipEditor=False 并保存 → 回读 False   ✓ 保存生效
      B 用**陈旧快照**(仍以为 True)改别的字段并保存
      → 回读 regionSkipEditor=True  ← A 的改动被静默抹掉

**机制**:SettingsDrawer.qml 的 save() 是"先 get_settings 拿一份快照 → 改 UI 上那
几个字段 → **整份**回写 save_settings"。核心侧 save_settings 是**整体替换**
(core.set_settings(settings)),不做字段级合并。于是:

- 同一面板内:输入框 textEdited 去抖 400ms 触发保存(见 autoSave Timer),
  用户在 400ms 内又改了另一个控件 → 后一次保存带的是**上一次的快照**,
  前一次的改动被覆盖 —— 表现就是"我明明改了,它自己变回去";
- 跨入口:托盘/热键链路读设置、面板另存一份快照,交错写同理会互相覆盖。

**这不是校验拒绝**(7 个复选框逐个翻转,save_settings 全部返回 ok=true),
而是**写覆盖**。修复方向见 §18.6 F1。

> 另注:我第一次探测时传了**裸对象**(少一层 settings 信封),导致"只有最后一项
> 落盘"的假象 —— 那是探测方式的错误,不是产品缺陷。真实 UI 路径(get→全量回写)
> 在**单次**往返下是可靠的。这条记下来是为了避免后人重复走这条弯路。

## 18.4 两个开关语义冲突 + 编辑入口收敛(需求 ③)

**现状**:两个独立布尔量叠出**四种**组合,其中两种无意义/冲突:

| regionSkipEditor | regionAutoConfirm | 实际行为 |
| --- | --- | --- |
| true(默认) | true(默认) | 松手 → 直接入库+剪贴板 |
| true | false | 松手 → 保留选区+浮条,但浮条的「完成」**跳过编辑器**;浮条存在却无编辑器 |
| false | true | 松手即确认 → 进编辑器(**与"松开即确认"的字面意思矛盾**) |
| false | false | 松手 → 保留选区+浮条 →「完成」→ 编辑器 |

后两种组合正是用户说的"语义冲突":**「松开鼠标即确认」与「进编辑器」不可能同时成立**。

**重构设计**:两者本质是**同一个问题的两个选项** —— "框选之后去哪儿":

    框选松手 → 三选一的**单一**出口(取代两个布尔量):
      A. 直接入库 + 写剪贴板(默认;快)

## 18.8 工具条布局与「手型可逆」(第二轮用户反馈)

### 问题 ①:默认手型后,点了工具就切不回抓手

**根因**:m_drawingTool 一旦置 true 永不复位 —— EditorWindow::setTool() 与工具条的
toolChanged 回调都只写 = true。于是流程图变成单向:抓手 → 可绘制,回不去。

**改法**:工具行最前面加一个手型按钮,与绘图工具同一互斥组:

    工具行:[手型] [画笔][箭头]…[取色] | [七色]
    参数行:[粗细×3][字号×3][撤销][重做]        ……  [宿主动作按钮(右)]

- 选手型 → drawingModeChanged(false) → 画布回拖动态,光标 = 手型;
- 选任一绘图工具 → drawingModeChanged(true) → 画布可绘制,光标 = 工具光标;
- 两个方向都可逆 —— 这是「切不回来」的解法;
- 手型激活时禁用颜色/粗细/字号(对手型无意义,不隐藏以免宽度跳动)。

手型是「画布模式」而非绘图工具,故用 QAction::data = -1 与 EditorTool 枚举值区分,
不进引擎的工具集(引擎不知「手型」这个概念)。

**顺带清掉一处死代码**:EditorWindow::setTool() 已无任何调用者(工具切换完全由
共享工具条驱动),而它内部那句 m_drawingTool = true 正是「不可逆」的来源之一。已删。

### 问题 ②:按钮全堆在左下角,布局不合理

**改法**:参数行改为「左:参数 / 右:动作」两段(中间 addStretch(1)):

    之前: [工具…][颜色…]
           [粗细][字号][撤销][重做][另存][贴图][OCR][完成][取消]   ← 全左对齐

    现在: [手型][工具…][颜色…]
           [粗细][字号][撤销][重做]              [另存][贴图][OCR][缩放][完成][取消]
                                                  ↑ 宿主动作,靠右下角

- 实现:AnnotationToolbar::setTrailingWidget() —— 宿主(编辑器)把自己的动作条
  挂进参数行右侧。这样「工具在左、执行在右」由共享控件保证,浮条将来接入时
  自动获得同一布局,不必各写一遍;
- m_paramsRow 存为成员而不是靠 parentWidget() 反查(反查依赖 reparent 时序,易静默失效)。

### 另一处顺带修正

取色器采样后引擎会自行把工具切回上一个绘图工具(引擎 onCanvasPressed 的行为),
而工具条不会自动知道 → 会停在「取色」高亮的错误状态上。已在 onCanvasPressed 里

## 18.12 编辑页「贴图」无效:pinRequested 成了孤儿信号

用户反馈:编辑页面点「贴图」,没成功贴图。

根因(排查链):

    EditorWindow::pinToScreen() -> emit pinRequested(composed) -> close()
                                        |
                        全工程 grep: emit 1 处、声明 1 处、connect 0 处

信号发出后没有任何连接方。历史上唯一接过它的是框选链路
(capture_session 的 regionConfirmed 编辑器分支,F3 已整段删除)。
框选链路下线后,编辑器仅剩两个入口(右键条目编辑 / 贴图工具条编辑),
两处创建 EditorWindow 时都只连了 committed,漏了 pinRequested ——
点「贴图」= 编辑器关闭、贴图窗口没建。这不是本轮回归,是右键入口诞生起就缺的。

修法:两处入口都补连 pinRequested,口径与 committed 一致(入库 + 写剪贴板):

| 入口 | 连接后行为 |
| --- | --- |
| 右键条目「编辑」 | 入库 + clipChanged + 开贴图窗口 |
| 贴图工具条「编辑」 | 入库 + clipChanged + 开贴图窗口 + 回写原贴图(guard 存活时 setImage) |

教训:删除一条链路时,要 grep 它独有的信号/回调还有没有别的生产者。
pinRequested 这种只有一个消费者的信号,消费者随链路删掉后就成了孤儿 ——
编译器不报错(信号没人是合法的),只有运行时行为缺失能暴露。

验证:改动文件编译 CL-EXIT=0、无警告;实机路径 = 右键编辑 → 贴图按钮。
