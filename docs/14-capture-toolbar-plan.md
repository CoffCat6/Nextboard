# 15. 截图工具栏化:编辑器 UI 改造 + 新功能(方案)

> 需求:截图确认后**不再弹独立编辑窗口**,改为在**选区底部悬浮工具栏**;
> 功能:编辑(标注)、复制、贴图、保存、OCR 取字。
> 本节为**代码侦察 + 设计方案,未写代码**。

## 15.1 两种产品形态(需要拍板)

### 形态 A:选区底部悬浮工具栏(截图工作流主流形态,微信/Snipaste 式)

    ┌─────────────────────────┐
    │      遮罩 + 选区          │
    │   ┌───────────────┐     │
    │   │   选区(亮)     │     │
    │   └───────────────┘     │
    │  [标注][复制][贴图][保存][OCR][✓][✕]  ← 选区底部紧贴
    └─────────────────────────┘

- **不弹独立窗口**:确认选区 → 底部浮条出现 → 各按钮就地生效;
- 标注工具选中后浮条展开二级(颜色/粗细),画布仍是遮罩上的冻结底图;
- 「完成」= 合成 → 入库 + 剪贴板(即原编辑器 committed 语义)。

### 形态 B:保留独立编辑窗口,工具栏**移到底部**(改动最小)

    ┌─────────────────────────┐
    │      画布(标注)          │
    ├─────────────────────────┤
    │ [标注][复制][贴图][保存][OCR][✓][✕] │  ← 底部,单行
    └─────────────────────────┘

- `QVBoxLayout` 从「工具栏在上」改为「画布在上、工具栏在下」,两行并一行;
- 标注逻辑(QUndoStack/图元/马赛克/文字烘焙)**零改动**;
- 新增复制/贴图/OCR 按钮;
- ❗ 但它仍是一个**独立窗口**,不符合「截图跳出工具栏」的原意 ——
  选区确认后屏幕上仍是先弹窗再操作,交互链路与主流截图工具不同。

| | 形态 A(悬浮工具栏) | 形态 B(编辑窗底部栏) |
| --- | --- | --- | --- |
| 交互感受 | 与主流一致,快照级操作少一次窗口弹出 | 仍多一次窗口弹出 |
| 工作量 | 大(遮罩上实现标注 + 浮条组件) | **小**(布局改位 + 加按钮) |
| 风险 | 中(标注坐标系要从场景坐标迁到遮罩局部坐标) | 低 |
| 复用 | 标注引擎可复用,但宿主层重写 | **全部复用** |

> 💡 **建议:分两步走** —— 先做 **B**(小步,把功能补齐:复制/贴图/OCR),
> 验证功能与 FFI 链路后,再做 **A**(把窗口形态改悬浮)。这样 A 失败也不损失功能。

## 15.2 功能清单与实现要点

### 新增按钮(工具栏)

| 按钮 | 语义 | 实现路径 | 难度 |
| --- | --- | --- | --- |
| **复制** | 把当前合成图写入剪贴板 | 已有 `ingestImageAndCopy`(先入库后写剪贴板,§0 事实 5)或轻量只写剪贴板 | 低 |
| **贴图** | 把当前合成图作为置顶贴图 | 复用 `showPinWindow(PinContent{image=compose(), idPrefix})` | 低 |
| **保存** | 另存为 PNG | 已有 `saveToFile()`,挪个按钮即可 | 无 |
| **OCR 取字** | 对**当前合成图**识别 → 文本入剪贴板/弹结果 | **需新增 FFI**(见 §15.3) + 异步执行 | 中 |

### 关键设计点

1. **OCR 对象是「当前合成图」**:`compose()` 已有,直接喂 OCR —— 不需要先入库;
2. **OCR 必须异步**:det 推理 0.4~5s(全屏),在 UI 线程会卡死工具栏;
   → `QThreadPool` + 完成后回 UI 线程(`CoreFacade::ocrEntry` 已是此模式,照抄);
3. **贴图后工具栏何去何从**:贴图 = 独立功能,贴完**不关**编辑器(用户可能还想标注);
   复制/OCR 同理 —— 只有「完成/取消」才结束会话;
4. **OCR 结果展示**:复用现有 toast?还是弹一个小文本框可复制?
   建议:**小弹层显示文本 + 「复制」按钮**(截图取字的核心诉求就是复制走人);
5. **PinWindow 的编辑闭环**:贴图后点贴图工具条「编辑」会再开编辑器 ——
   与本编辑器是两个实例,不冲突,但要留意内存(docs/06 曾实测编辑器持有 ~98MB)。

## 15.3 OCR FFI 设计(必须新增)

### 形态:仿 `nb_capture_crop` 的「宿主传 RGBA → 核心返回」

    #[no_mangle]
    pub unsafe extern "C" fn nb_ocr_rgba(
        rgba: *const u8, len: usize, width: u32, height: u32,
        out_text: *mut *mut i8,   // JSON {"text": ...} 或按现有 out 协议
    ) -> i32

- 内部调 `crate::ocr::recognize_configured(rgba.to_vec(), w, h, &OcrOptions::from_settings(...))` —— **设置联动天然生效**(后端/偏好/驻留全用上);
- 生命周期:`out_text` 由 Rust 分配,宿主 `nb_free_string` 释放(与 `nb_call` 同约定);
- **无需走 `nb_call` JSON 通道**(它是字符串协议,传 8MB RGBA 会 base64 膨胀 33% 且序列化慢 —— `nb_capture_*` 特意用指针通道,这里同理);
- ABI 注意:纯新增导出函数,不破坏现有 ABI v1。

### 宿主侧(CoreBridge)

    QImage → 转 RGBA(已编好) → nb_ocr_rgba → 解析 JSON → QString 文本
    线程池执行,完成回 UI 线程(照抄 CoreFacade::ocrEntry 模式)

## 15.4 遮罩层改造要点(形态 A,第二步)

1. `OverlayWidget` 已有 `m_selection`(局部逻辑坐标)、冻结底图、手柄微调 ——
   工具栏就挂在选区底部(越界翻转到底部上方,靠边屏幕的常规处理);
2. 标注引擎迁移:`EditorWindow` 的图元/撤销栈逻辑需从「独立窗口的场景坐标」
   搬到「遮罩窗口的局部坐标」—— 坐标换算已在遮罩里成熟(选区→物理像素),
   但 `EditorCanvas`/`QGraphicsView` 的缩放逻辑要重审(遮罩上画布=1:1,不需要 fitCanvas);
3. 双窗口职责:标注在遮罩内,「完成」→ 合成 → 走既有 committed 通道;
4. **内存**:遮罩是整屏底图 + 编辑缓冲并存,比独立编辑窗多一份 ——
   需重测(docs/06 的坑:遮罩未析构会污染读数)。

## 15.5 实施顺序(建议)

| 阶段 | 内容 | 交付物 |
| --- | --- | --- |
| **P1** | FFI `nb_ocr_rgba` + CoreBridge 封装 + 单测 | 可从宿主直接对任意 QImage 做 OCR |
| **P2** | 编辑窗工具栏移到底部(布局改位) + 加「复制」「贴图」「保存」 | 功能全齐的形态 B |
| **P3** | 编辑窗加「OCR 取字」按钮(异步 + 结果弹层) | 形态 B 完整体 |
| **P4** | 遮罩底部悬浮工具栏(形态 A),标注引擎迁入遮罩 | 主流交互形态 |
| **P5** | 验收流 + 内存回归(docs/06 坑:遮罩析构时机) | 质量关 |

> 💡 P1~P3 是**纯增量**(独立窗口保留),P4 才是形态切换 —— 风险隔离。
