## 2026-10-07(三)三个真机缺陷根因与修复(翻译独立窗口引入的回归)

用户反馈:①设置页无法进入;②翻译窗口目标语言下拉框文字看不清;③翻译按钮消失、无法翻译。

### 定位方法(有效)

读 `app/build/nextboard.log`(追加式,找最后一次 `Nextboard starting` 之后的行)。
日志直接给出三条证据,避免猜测:

```
[WARN] ThemedButton.qml:27:5: Unable to assign [undefined] to double      ×12
[WARN] Singleton registered by registerSingletonInstance must only be accessed from one engine
[CRIT] qmlRegisterSingletonType(): "Core" is not available because the callback returns a null pointer.
[WARN] Theme.qml:12:5: Unable to assign [undefined] to bool
[WARN] TranslateWindow.qml:74: TypeError: Property 'translateText' of object Nextboard.Core/Core is not a function
[WARN] ReadableComboBox.qml:46: ReferenceError: index is not defined
[WARN] ReadableComboBox.qml:48: TypeError: Type error
```

### 根因 1:单例绑死单引擎 → 翻译窗口里 Core 全废

`qmlRegisterSingletonInstance` 把单例绑定到**单个** `QQmlEngine`。本次新增的翻译窗口
QQuickWidget 创建了第二个引擎,而两个引擎**并存** → 第二个引擎取到 null。
→ 翻译窗口里 `Core.*` 全部不可用;`Theme` 也拿不到 `darkTheme`。

**证据**:写了临时探针 `tools/singleton_probe`(控制台程序,沙箱内可运行),
两引擎并存下对比两种注册方式:

```
A registerSingletonInstance  engine0=4242 engine1=-1     ← 现状,第二引擎失败
B registerSingletonType      engine0=4242 engine1=4242   ← 修复后可用
```

**修复**:`qml_bootstrap.cpp` 改用 `qmlRegisterSingletonType` 回调式注册
+ `QQmlEngine::setObjectOwnership(..., CppOwnership)`(引擎不得接管生命周期)。
`Core` / `Entries` 各一处。探针已删除。

### 根因 2:ThemedButton 的 implicitWidth 被赋 undefined

`implicitWidth: square ? implicitHeight : undefined` → `Unable to assign [undefined] to double`
→ 宽度失效为 0 → **按钮在布局里整个消失**。
主面板「设置 / 翻译」按钮即此原因 → 设置页进不去;翻译窗口主按钮消失 → 无法触发翻译。

**修复**:非 square 分支改为 Control 的默认推算
`Math.max(implicitBackgroundWidth + leftInset + rightInset, implicitContentWidth + leftPadding + rightPadding)`。

### 根因 3:ComboBox 委托用错 required 属性名

**权威依据**:Qt 官方 `qml/QtQuick/Controls/Basic/ComboBox.qml`(该文件的 QML 源码
随 windeployqt 原样部署在 `app/build/qml/` 下,可直接读)明确写着:

```qml
delegate: ItemDelegate {
    required property var model     // ← delegateModel 提供的是 model(整项),不是 modelData
    required property int index      // ← index 必须显式声明才注入
    text: model[control.textRole]
}
popup: T.Popup { ... palette: control.palette }
```

原代码写的是 `required property var modelData`(名字不对 → 取值为空),
且一旦声明 required 属性、`index` 就必须同样声明,否则不再注入
(`ReferenceError: index is not defined`)→ 下拉项整片渲染异常。
另外弹窗是独立窗口、不继承应用调色板,官方同样是显式 `palette: control.palette`。

**修复**(`ReadableComboBox.qml`,完全对齐官方实现):
`required property var model` + `required property int index` +
`text: control.textRole ? model[control.textRole] : model`(本项目全是纯字符串 model)
+ `popup.palette: control.palette`。

### 顺带

- `TranslateWindow.qml` 的 `targetLang` 从 `textRole/valueRole` + 对象数组
  改为**纯字符串 model + 平行 `langCodes` 数组**(与 ReadableComboBox 的注入方式匹配),
  `loadTargetLang` / `doTranslate` 同步改用 `langCodes[…]`。

### 环境结论(重要,已验证到边界)

- `build.ps1` 在本沙箱**确定不可用**:其依赖 `vcvars64.bat` → `reg.exe`,
  而 `reg.exe` 在程序黑名单中且**不可绕过**(即使关闭沙箱)。等价做法:手工注入
  `INCLUDE` / `LIB` 后直接跑 `D:/Qt/Tools/Ninja/ninja.exe`(见 MEMORY.md)。
- GUI 子系统程序(`nextboard.exe`)在沙箱内**无法启动**(exec 直接返回 127);
  链接 Qt6Gui 的控制台程序同样 127 → 即"加载 Qt6Gui 的进程"被拦。
  纯 Qt6Qml 控制台程序可正常运行 —— 这是本次能用探针验证单例行为的原因。
- 已把 `qoffscreen.dll` 拷到 `app/build/platforms/`,但上述拦截与平台插件无关。

### 验证

- app `ninja` 重建 **0 error / 0 warning**;qmllint 无 Error、无新增告警;
  Qt QML 模块部署校验全 OK(未引入新 import)。

## 2026-10-07(四)下拉项文字为空 —— 第三层根因(QQmlDMListAccessorData)

用户回传截图:翻译窗口整体已正常(按钮/文案/布局都在),**仅下拉弹层的选项文字为空**
(弹层有高度、有底色、首项还有高亮灰底 → 委托确实在生成,只是 text 取不到值)。

### 新日志(本次只剩一条,其余全干净 → 前三个修复已生效)

```
[WARN] ReadableComboBox.qml:61: Unable to assign QQmlDMListAccessorData to QString  ×8
```

**根因**:ComboBox 的 delegateModel 以 required 属性提供的 `model` 是
**`QQmlDMListAccessorData` 访问器对象**(可按下标/角色名取值的包装),**不是模型项本身**。
把它直接赋给 `text`(QString)必然失败 → 空文字。
即:`text: model` 和 `text: control.textRole ? model[control.textRole] : model` 都错。

**正确做法**:用 ComboBox 自带的 `textAt(index)`
(`Q_INVOKABLE`,已由 `qml/QtQuick/Templates/plugins.qmltypes:1604` 与
`Qt6QuickTemplates2.dll` 确认存在)。它与关闭态显示的 `displayText` 是同一套 C++ 逻辑
(空 textRole 时返回 modelData 本身),因此**只要关闭态能正确显示文本,下拉项就一定能**。

**修复**:`delegate` 改为 `required property int index` +
`text: control.textAt(itemRoot.index)`(不再声明/使用 `model`)。

### 顺带(弹层几何)

`ReadableComboBox` 的 popup 增加高度收敛,避免长列表弹层跑出屏幕导致底部选项点不到:
`height: Math.min(contentItem.implicitHeight, Window.height - control.height - 16)`。

### ComboBox 委托四层坑(完整清单,勿再踩)

1. `required property var modelData` 名字不存在 → 取值为空;
2. 声明了 required 属性后 `index` 必须**同样声明**,否则 `ReferenceError: index is not defined`;
3. `model` 是 `QQmlDMListAccessorData` 访问器 → 不能直接当文本/字符串用;
4. 弹窗是独立窗口,必须显式 `palette: control.palette`。
   → **结论:委托文案一律用 `control.textAt(index)`,不要碰 `model`/`modelData`。**
